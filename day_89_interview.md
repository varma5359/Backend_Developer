# Day 89: Interview Questions — Capstone: Business Problem, Requirements and System Design

**Pathway:** Python Backend Developer Career Pathway (Django)  
**Phase:** 8 — End-to-End Backend Capstone  
**Related notes:** [Day 89 class notes](day_89_notes.md)  
**Capstone:** Employee and Project Management System — Django Backend and REST API  
**Approved deliverable:** Backend Project Requirements

## Core questions

### Q1. Explain capstone: business problem, requirements and system design.
**Answer:** The capstone is an Employee and Project Management System. An organization currently tracks employees, departments, projects and tasks in spreadsheets. The backend should centralize these records, support controlled access, expose REST APIs and provide an auditable workflow. Day 89 turns the business need into clear requirements and a system design before implementation begins.

### Q2. What deliverables did you create?
**Answer:** Write the business problem and target users. Identify roles: administrator, HR, project manager and employee. Define functional requirements for employees, departments, projects, tasks and notifications. Define non-functional requirements for security, reliability, maintainability and performance. Write user stories and acceptance criteria. Identify core entities and relationships. Draw the high-level architecture and request flow. List API resources and likely operations. Record assumptions, constraints, risks and out-of-scope features. Create a day-by-day implementation plan for Days 90–96.

### Q3. What is one design decision?
**Answer:** Explain one decision, the alternatives and why your choice meets the requirement.

### Q4. How did you validate the work?
**Answer:** Problem statement is clear and business-focused. Roles and responsibilities are defined. Functional requirements are testable. Non-functional requirements are measurable where possible. Core entities and relationships are identified. Architecture and API boundaries are documented. Risks and assumptions are recorded. Acceptance criteria are agreed before coding.

### Q5. What remains incomplete or out of scope?
**Answer:** Identify limitations honestly. Do not claim a feature is complete unless it is implemented and tested.

## Scenario-based questions

### Q6. A stakeholder requests a new feature late in the capstone. How do you respond?
**Suggested answer:** Compare it with the approved scope, estimate impact on dependencies and testing, document the decision and avoid destabilizing required deliverables.

### Q7. How do you explain the design to an interviewer?
**Suggested answer:** Start with the business problem, describe the architecture, show the implementation, explain a key trade-off and demonstrate test evidence.
